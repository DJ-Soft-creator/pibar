# 0005 – Translations without a library, English text as key

Status: accepted
Date: 2026-10-31

## Context

PiBar started with a German UI and should be usable in English and German, with room for more languages. Libraries
such as i18next add a dependency and a separate key scheme.

## Decision

- English is the project language for code, comments and docs.
- UI text is written in English and used as the key: [`t`](../../src/shared/i18n.ts)`("Close session")`. Other languages
  are dictionaries in the same file; TypeScript ensures every German entry exists for a key that is used.
- Static HTML uses `data-i18n`, `data-i18n-title` and `data-i18n-placeholder`, filled by
  [`translateDom`](../../src/shared/i18n.ts); a test checks that every such key has a translation.
- Messages from Rust (errors, tray menu) use [`tr`](../../src-tauri/src/i18n.rs)`(english, german)` right where they
  are produced; the UI tells Rust the active language.
- The setting is "auto" (system language), "en" or "de"; a change reloads both windows.

## Consequences

- No extra dependency; plurals and formats are handled by `Intl` and small helpers.
- A third language means one more dictionary and a third argument (or a table) for `tr` in Rust.
